# برگشت تغییرات در گیت، به تفصیل

سه ابزار اصلی برای «برگشتن» وجود داره و انتخاب درستش بستگی به این داره که تغییرات کجا هستن.

```text
Working directory  --git add-->  Staging area  --git commit-->  Repository
     (فایل‌ها)                      (stage)                       (تاریخچه)
```

## ۱. تغییرات هنوز commit نشده

**فایل ویرایش شده و می‌خوام تغییراتش رو دور بریزم:**

```bash
git restore file.txt
```

**فایل رو add کردم ولی نمی‌خوام توی کامیت بعدی باشه:**

```bash
git restore --staged file.txt
```

**همه‌ی تغییرات commit نشده رو دور بریزم (خطرناک!):**

```bash
git restore .
git clean -fd      # حذف فایل‌ها و پوشه‌های untracked
```

> قبل از `git clean` حتماً یک بار `git clean -nd` بزن تا ببینی چه چیزی حذف می‌شه.

## ۲. آخرین کامیت اشتباه بود

**فقط پیام رو اصلاح کنم:**

```bash
git commit --amend -m "پیام جدید"
```

**یک فایل یادم رفته بود:**

```bash
git add forgotten.txt
git commit --amend --no-edit
```

> `--amend` کامیت رو بازنویسی می‌کنه. اگر قبلاً push شده، بعد از amend باید `git push --force-with-lease` بزنی. این کار فقط روی شاخه‌ی شخصی خودت امنه.

## ۳. چند کامیت اخیر رو برگردونم: reset

| حالت | کامیت‌ها | stage | فایل‌ها |
|---|---|---|---|
| `--soft` | برگشته | تغییرات در stage می‌مونن | دست‌نخورده |
| `--mixed` (پیش‌فرض) | برگشته | خالی می‌شه | دست‌نخورده |
| `--hard` | برگشته | خالی می‌شه | **پاک می‌شن** |

```bash
git reset --soft HEAD~1     # آخرین کامیت رو بردار ولی کارهام در stage بمونه
git reset HEAD~3            # سه کامیت آخر رو بردار، فایل‌ها بمونن
git reset --hard HEAD~1     # آخرین کامیت و تغییراتش رو کامل حذف کن
```

## ۴. روی شاخه‌ی مشترک: revert

وقتی کامیت push شده و بقیه هم ازش استفاده می‌کنن، تاریخچه رو بازنویسی نکن. به‌جاش یک کامیت معکوس بساز:

```bash
git revert <commit-hash>
git revert HEAD              # خنثی کردن آخرین کامیت
git revert -m 1 <merge-hash> # خنثی کردن یک merge commit
```

## ۵. نجات‌دهنده: reflog

بعد از یک `reset --hard` اشتباهی یا حذف شاخه، کامیت‌ها معمولاً هنوز وجود دارن:

```bash
git reflog                   # تاریخچه‌ی حرکت‌های HEAD
git reset --hard HEAD@{2}    # برگشت به وضعیت دو حرکت قبل
git switch -c rescued <hash> # ساخت شاخه‌ی جدید روی یک کامیت گم‌شده
```

گیت کامیت‌های بی‌صاحب را بعد از مدتی (به‌طور پیش‌فرض حدود ۳۰ تا ۹۰ روز) پاک می‌کنه، پس زود اقدام کن.

## خلاصه: کدوم رو بزنم؟

| وضعیت | دستور |
|---|---|
| تغییرات commit نشده | `git restore` |
| آخرین کامیت (push نشده) | `git commit --amend` یا `git reset` |
| چند کامیت (push نشده) | `git reset` |
| کامیت push شده | `git revert` |
| همه چیز خراب شد | `git reflog` |
